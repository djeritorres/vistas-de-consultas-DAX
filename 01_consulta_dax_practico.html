Pregunta 1 · Conocimiento general

¿Cuántos tipos de resultado devuelve DAX?

🔢 Valor escalar 1 VALOR

Un único valor: un número, un texto, una fecha o un valor verdadero/falso.

▦ Tabla N FILAS

Un conjunto de filas y columnas.

Respuesta: Dos. Toda expresión DAX devuelve un valor escalar o una tabla.
¿Qué es un valor escalar? Es un solo dato: un número, un texto o una fecha. Por ejemplo, el total de ventas del año o el nombre de un cliente. Una tabla, en cambio, tiene varias filas y columnas.
Pregunta 2 · Conocimiento general

¿Cómo saber si el resultado de una función es un valor escalar o una tabla?

OPCIÓN 1

Probando

Escribe la función y mira qué devuelve. Si es un valor escalar, se crea una medida; si es una tabla, una tabla calculada.

OPCIÓN 2

Leyendo la documentación

Cada función indica su valor devuelto: un escalar o una tabla.

OPCIÓN 3

Mirando el error

Si usas una tabla donde se espera un escalar (o al revés), DAX te lo dice.

¿Qué funciones conoces que devuelvan un valor escalar o una tabla?

🔢 Valor escalar

▦ Tabla

Devuelven filas y columnas.

Dato curioso

¿Sabías que hay funciones que devuelven un valor escalar y una tabla al mismo tiempo?

Devuelven una tabla de una sola columna y una sola fila. Cuando DAX espera un valor escalar, la usa como tal.
No son las únicas: esto aplica a cualquier expresión que devuelva una tabla de una columna y una fila. Si tiene más filas, DAX da error al usarla como escalar.
FECHAS

LASTDATE · FIRSTDATE

Última y primera fecha visible en el contexto.

FECHAS

ENDOFMONTH · STARTOFMONTH

También existen para trimestre (QUARTER) y año (YEAR).

CON DATOS

LASTNONBLANK · FIRSTNONBLANK

Última y primera fecha que tiene un valor.

COLUMNAS

VALUES · DISTINCT

Con un solo valor visible, se usan como un escalar.

¿Por qué importa?

Identificar el tipo de resultado y usarlo con CALCULATE

  • Los filtros de CALCULATE esperan una expresión lógica o una tabla.
  • Si en un filtro colocas una función que devuelve un valor escalar, el resultado es un error o no es el esperado.
  • Saber qué devuelve cada función evita esos errores.

El reto de DAX

Depurar funciones de tabla: lo más difícil de entender

Power BI no tiene un depurador que muestre el paso a paso de una fórmula con funciones que devuelven una tabla.
Ventas Top Clientes =
VAR _Clientes_Con_Ventas =
    VALUES( Cliente[NombreCliente] )
VAR _Top_3 =
    TOPN( 3, _Clientes_Con_Ventas, [Venta Total], DESC )
VAR _Resultado =
    CALCULATE( [Venta Total]
        , _Top_3
    )

    RETURN
    _Resultado
Dos variables guardan tablas intermedias que no podemos ver.

1 · Contar las filas

COUNTROWS( _Top_3 ) dice cuántas filas tiene la tabla.

2 · Concatenar los valores

CONCATENATEX( _Top_3, Cliente[NombreCliente], ", " ) muestra las filas en una tarjeta.

3 · Funciones nuevas

TOJSON( _Top_3 ) y TOCSV( _Top_3 ) devuelven la tabla completa como texto, sin indicar las columnas. Artículo de SQLBI.

Ejercicio 3

Agrupar con SUMMARIZECOLUMNS y SUMMARIZE

1 · SUMMARIZECOLUMNS

Por año y categoría

EVALUATE
SUMMARIZECOLUMNS(
  Calendario[Año]
  , Producto[Categoria]
  , "Cantidad", SUM( Ventas[Cantidad] )
)

ORDER BY Calendario[Año] ASC, [Cantidad] DESC
2 · SUMMARIZE

Con Calendario como base

EVALUATE
SUMMARIZE( Calendario
  , Calendario[Fecha]
  , "Cantidad", SUM( Ventas[Cantidad] )
)

ORDER BY Calendario[Fecha] ASC
3 · SUMMARIZECOLUMNS

Por fecha

EVALUATE
SUMMARIZECOLUMNS(
  Calendario[Fecha]
  , "Cantidad", SUM( Ventas[Cantidad] )
)

ORDER BY Calendario[Fecha] ASC
4 · SUMMARIZE

Con Ventas como base

EVALUATE
SUMMARIZE( Ventas
  , Calendario[Fecha]
  , "Cantidad", SUM( Ventas[Cantidad] )
)

ORDER BY Calendario[Fecha] ASC
  • EVALUATE inicia toda consulta DAX y devuelve una tabla. Es la única palabra obligatoria; ORDER BY y el resto son opcionales.
  • ORDER BY (opcional) ordena el resultado y va al final de la consulta.
  • ASC ordena de menor a mayor y DESC, de mayor a menor.
  • SUMMARIZECOLUMNS es lo que Power BI genera por debajo para una matriz: columnas de agrupación y luego las medidas.
  • SUMMARIZE devuelve las filas de su primer argumento: con Calendario salen todas las fechas, y con Ventas solo las que tienen ventas.
  • Prueba: añade Territorio[Pais] como tercera columna de agrupación en la tarjeta 1.

Ejercicio 4

Definir una medida con DEFINE

DEFINE
  MEASURE Medidas[Ventas YTD] =
    CALCULATE( [Venta Total]
      , DATESYTD( Calendario[Fecha] )
    )

EVALUATE
SUMMARIZECOLUMNS(
  Calendario[Año], Calendario[Mes],
  "YTD", [Ventas YTD]
)
  • DEFINE abre la sección donde declaras medidas, variables o tablas que solo viven en la consulta.
  • MEASURE crea una medida temporal con la forma Tabla[Nombre] = fórmula. La tabla indica dónde se guardaría la medida si la llevas al modelo.
  • La medida solo existe dentro de la consulta: no toca el modelo.
  • Puedes probarla y corregirla las veces que haga falta.
  • Si una medida del modelo se llama igual, la de DEFINE tiene prioridad en esa consulta.

Ejercicio 5

Ordenar con VAR y RETURN

DEFINE
  MEASURE Medidas[Crecimiento %] =
    VAR _Actual   = [Venta Total]
    VAR _Anterior =
        CALCULATE(
            [Venta Total]
            , SAMEPERIODLASTYEAR( Calendario[Fecha] )
        )
    VAR _Resultado = DIVIDE( _Actual - _Anterior, _Anterior )
    RETURN
        _Resultado

EVALUATE
SUMMARIZECOLUMNS( Calendario[Año], "Crec", [Crecimiento %] )
  • VAR guarda un cálculo en una variable que se evalúa una sola vez y se puede reutilizar.
  • RETURN indica el resultado final: es lo único que devuelve la medida.
  • Los nombres de las variables empiezan con guion bajo, por ejemplo _Actual.
  • Para ver un paso intermedio, cambia el RETURN y devuelve solo _Anterior.
  • Con Shift+Alt+F das formato al código.

Ejercicio 6

Documentar el modelo con INFO

// Todas las medidas y su código
EVALUATE
INFO.MEASURES()

// Tablas y columnas del modelo
EVALUATE
INFO.TABLES()

EVALUATE
INFO.COLUMNS()
Ejecuta cada EVALUATE por separado: se ejecuta la consulta donde está el cursor.
// Solo las columnas calculadas y su fórmula
EVALUATE
SELECTCOLUMNS(
  FILTER( INFO.COLUMNS(), [Type] IN { 2, 4 } ),
  "Columna", [ExplicitName],
  "Fórmula", [Expression]
)
  • Las funciones INFO devuelven los metadatos del modelo como tablas.
  • Las funciones INFO.VIEW son la versión legible de cuatro INFO: tablas, columnas, medidas y relaciones. Muestran nombres y tipos en texto en lugar de códigos.
  • Diferencia clave: las INFO solo sirven en la vista de consulta DAX; las INFO.VIEW también sirven en tablas calculadas y medidas.
  • Sirven para auditar medidas o pasar la lista a la IA como contexto.

Reto final

Clientes nuevos y perdidos

  • 1. Obtén la tabla de clientes del año con VALUES( Ventas[IdCliente] ).
  • 2. Obtén los clientes del año anterior con CALCULATETABLE y DATEADD.
  • 3. Clientes perdidos: los que compraron el año anterior y este año no, con EXCEPT.
  • 4. Clientes nuevos: los que compraron este año y nunca habían comprado antes, con EXCEPT y todas las fechas previas.
  • 5. Cuenta las filas con COUNTROWS, pruébalo en la vista de consulta y llévalo a Medidas.
